# Workflow

## Work lifecycle

Backlog → Planned → In Progress → Analysis Complete →
Documentation Complete → Portfolio Ready → Completed

Use only the stages relevant to the deliverable.
A schema, glossary, or planning task can be completed once its own
acceptance criteria pass; it does not need to become a standalone portfolio.

## Issue closure

Close an issue only after its acceptance criteria and evidence are complete.
Set its Project Status to Completed.
Repository milestone progress is calculated from open and closed issues.

## Branch and pull request

Create a branch for a coherent change, commit the work, push the branch,
and open a pull request. Link the issue with "Refs #NUMBER".
Use "Closes #NUMBER" only for a change that completes the whole issue.

## Skills

Use skill:* labels. Skills are not stored in a custom multi-select field.

## Progress

Track three separate measures:
1. Setup: infrastructure work completed.
2. Deliverables: closed work issues / all defined work issues.
3. Portfolio readiness: featured projects passing the final checklist.

Issue counts are an unweighted scope measure, not a measure of hours,
difficulty, or demonstrated proficiency. Split or revise tasks when needed.
Do not treat setup completion as completion of the analysis.

## Publication

Check the actual data and course-material permissions before publication.
